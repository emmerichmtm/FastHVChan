# fasthvchan-c

A C99 port of this repository's `chan_hypervolume.py` — the exact hypervolume
indicator and Klee's measure problem via Chan's (FOCS 2013) divide-and-conquer.
It reads the Python original from the parent directory for its differential
tests; override with `FASTHVCHAN_PATH` if you move it.

This covers the **Section 2 algorithm** only. The Section 4.2 orthant engine
(`chan_orthant_dby3.py`) is not ported; see [Scope](#scope).

## Build

```sh
make            # libfasthvchan.a + test_fasthvchan
make test       # self-contained suite, no Python needed
make check      # differential test against the Python original
make bench      # timings on spherical fronts
```

No dependencies beyond libm. `make CC=clang` to switch compilers.

## Use

```c
#include "fasthvchan.h"

double points[9] = {0.2,0.7,0.3,  0.5,0.2,0.6,  0.8,0.4,0.1};  /* 3 x 3, row-major */
double ref[3]    = {1.0, 1.0, 1.0};

double hv = fhv_hypervolume(points, 3, 3, ref, /*maximize=*/0, /*prefilter=*/1);
/* hv == 0.31 */
```

| Function | Purpose |
|---|---|
| `fhv_hypervolume` | Hypervolume indicator w.r.t. a reference point |
| `fhv_union_volume` | Volume of a union of axis-parallel boxes (Klee's measure) |
| `fhv_nondominated` | Filter a point set to its non-dominated front |
| `fhv_reference_hypervolume` | Brute-force O(2^n) baseline, for cross-checking |

Points are flat `double` arrays of `n * dim`, row-major. Objectives are
minimised unless `maximize` is set. Full contracts are in `fasthvchan.h`.

## Validation

The port is checked two independent ways, both green:

- **`make test`** — 31 checks. The divide-and-conquer is compared against
  brute-force inclusion–exclusion for d=2..5, box unions for d=2..4, plus
  known values and edge cases (duplicates, empty input, degenerate boxes,
  reference dominating everything). Needs no Python.
- **`make check`** — 450 randomized cases generated by the Python
  implementation and replayed through the C port; all agree to within 1e-9.
  A separate large-input run (n up to 500, d up to 7) also agrees.

Node counts track the Python implementation closely on comparable inputs
(e.g. d=5: 13859 vs 13527), which is a structural check that the recursion is
behaving the same way and not merely landing on the same totals.

Speed on identical input, d=5 / n=150: Python 0.0819 s, C 0.0040 s — about 20x.

### Known gaps

- **No sanitizer run.** The MinGW-w64 toolchain used here ships no ASan/UBSan
  runtime (`cannot find -lasan`), so the memory-management paths have not been
  checked by a sanitizer, only by valgrind-free stress runs. Building with
  clang or on Linux and running `-fsanitize=address,undefined` is worth doing
  before trusting this in anything long-running.
- **Allocation failure is coarse.** Out-of-memory sets a sticky flag and the
  public functions return `FHV_ENOMEM` (-1.0). Since a genuine hypervolume is
  never negative the sentinel is unambiguous, but there is no errno detail.
- **Not thread-safe.** `fhv_node_count`, `fhv_base_case` and the comparator's
  dimension are globals, mirroring the Python class's mutable instance state.

## Scope

`chan_orthant_dby3.py` (the asymptotically faster O(n^(d/3) polylog n) Section
4.2 algorithm) is **not** ported. It is a symbolic engine — step functions with
pointwise min/max, antiderivatives, term algebra with bounds, pruning and
compression — roughly 1190 lines of Python that in C would need custom
allocators and hash maps at several times the source size. It is a separate
project, not a continuation of this one.

## Fidelity notes

Behaviour follows the Python source exactly, including details that a
from-scratch implementation might get differently:

- Python's `%` is non-negative for negative operands; the axis-renumbering
  weight uses `((k - depth) % dim + dim) % dim` to match.
- `nondominated` uses **weak** dominance after a lexicographic sort, so exact
  duplicate points are dropped, not kept.
- Degenerate (non-positive volume) boxes are silently dropped by
  `fhv_union_volume`, and an all-degenerate input gives 0.0.
- The weighted median sorts by `(coordinate, weight)`, matching Python's tuple
  ordering, and returns the first coordinate whose weight prefix reaches half.
